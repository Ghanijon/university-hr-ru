# 13. PDO: безопасные запросы и транзакции

Где смотреть в коде: `src/Core/Database.php`, `src/Core/Sql.php`, `src/Repositories/EmployeeRepository.php`,
`src/Services/TransferService.php`, `src/Repositories/LeaveRequestRepository.php`.

> Уязвимый код ниже — **только пример для чтения**. В проекте его нет.

## 13.1. Настройки соединения

| Опция | Зачем |
|---|---|
| `ERRMODE_EXCEPTION` | Ошибка SQL становится исключением: её нельзя не заметить, и в транзакции она ведёт в `catch` с `rollBack()` |
| `FETCH_ASSOC` | Строка — массив с именами столбцов, без дублей под номерами |
| `EMULATE_PREPARES = false` | Текст запроса и значения уходят в MySQL раздельно |
| `charset=utf8mb4` в DSN | Полный UTF-8; о кодировке знает и PDO, и сервер |

## 13.2. SQL-инъекция на примере поиска

### Плохо: значение вклеено в текст запроса

```php
// НЕ ДЕЛАЙТЕ ТАК
$sql = "SELECT * FROM employees WHERE last_name = '" . $_GET['q'] . "'";
$rows = $pdo->query($sql)->fetchAll();
```

Пользователь вводит `' OR '1'='1`, и MySQL получает:

```sql
SELECT * FROM employees WHERE last_name = '' OR '1'='1'
```

Кавычка закрыла строку, а остальное стало **кодом**. Условие `'1'='1'` верно всегда: запрос вернёт всех.

### Хорошо: подготовленный запрос

```php
$stmt = $pdo->prepare('SELECT * FROM employees WHERE last_name = :q');
$stmt->execute([':q' => $_GET['q']]);
```

MySQL сначала разбирает запрос с местом для значения, потом получает значение. Структура уже известна,
поэтому `' OR '1'='1` — просто странная фамилия. Таких сотрудников нет: результат пустой.

Проверьте сами: `GET /api/v1/employees?q=' OR '1'='1` → `"total": 0`.

### LIKE: отдельная забота

Параметр защищает от инъекции, но `%` и `_` внутри значения остаются спецсимволами LIKE.
Без экранирования поиск `%` нашёл бы всех.

```php
$params[':q'] = '%' . Sql::escapeLike($q) . '%';   // 100% → %100\%%
```

### IN(): один параметр — одно значение

`IN (:ids)` со строкой `'1,2'` не работает: это одно значение. Создаём плейсхолдер на каждое:

```php
[$in, $params] = Sql::in('status', ['active', 'on_leave']);
// WHERE status IN (:status_0, :status_1)
```

### ORDER BY: только белый список

Параметр передаёт **значение**, а столбец — часть текста запроса. `ORDER BY :sort` означало бы
«сортируй по константе `'hire_date'`», порядок бы не изменился. Поэтому ввод — лишь ключ:

```php
public const SORTS = ['last_name' => 'e.last_name', 'hire_date' => 'e.hire_date' /* … */];
```

Ключа в списке нет → 422. Сам ввод в SQL не попадает никогда.

## 13.3. Транзакция на примере перевода

Перевод — это два изменения: `UPDATE employees` (новое место) и `INSERT INTO orders` (приказ).
Если сбой случится между ними, сотрудник окажется переведён без приказа. Транзакция делает их единым целым:

```php
$db->beginTransaction();
try {
    // UPDATE employees …
    // INSERT INTO orders …
    $db->commit();      // оба изменения сохранены
} catch (Throwable $e) {
    $db->rollBack();    // ни одного изменения
    throw $e;
}
```

| ACID | Что значит для перевода |
|---|---|
| **A**tomicity — атомарность | Новое место и приказ появляются вместе или не появляются вовсе |
| **C**onsistency — согласованность | Внешние ключи и UNIQUE соблюдены: нет приказа без сотрудника и двух одинаковых номеров |
| **I**solation — изолированность | До `commit()` другие соединения не видят «переведён, но без приказа» |
| **D**urability — долговечность | После `commit()` перевод не пропадёт, даже если сервер выключится |

Доказательство: `tests/TransferTransactionTest.php`. Второй запрос намеренно падает (нет такого автора
приказа), и тест проверяет, что сотрудник не изменился.

## 13.4. Две блокировки

- **Пессимистическая** (перевод): `SELECT … FOR UPDATE` запирает строку до конца транзакции, остальные ждут.
- **Оптимистическая** (заявки): строку не запираем, но при записи проверяем, что она не изменилась:

```sql
UPDATE leave_requests SET status = :status, hr_decision_by = :user_id
WHERE id = :id AND status = :expected
```

`rowCount() === 0` — кто-то успел раньше → **409 Conflict**.
Поле `expected_status` в запросе API — статус, который пользователь видел на экране.
