# 15. Тестирование и исправление модулей

Документ — программа и методика испытаний проекта **university-hr**: виды тестирования,
тест-кейсы, баг-репорты на найденные ошибки и порядок запуска модульных тестов.

## 15.1. Виды тестирования в проекте

| Вид | Что проверяем | Чем | Где в проекте |
|---|---|---|---|
| Модульное (unit) | Отдельный класс без БД и браузера | PHPUnit | `tests/ValidatorTest.php`, `tests/LeaveRequestRulesTest.php` |
| Функциональное (ручное) | Сценарии пользователя по ролям | Браузер, тест-кейсы ниже | раздел 15.3 |
| Тестирование безопасности | SQL-инъекции, XSS, CSRF, права доступа, загрузка файлов | Браузер, DevTools, curl | TC-05 … TC-10 |
| Регрессионное | Исправленный баг не вернулся | Повтор тест-кейса после исправления | раздел 15.4 |
| Нефункциональное | Скорость, доступность, адаптивность | Lighthouse, DevTools (Device Toolbar) | раздел 15.6 |

**Чёрный ящик** — тестировщик не смотрит в код, проверяет поведение по ТЗ (тест-кейсы 15.3).
**Белый ящик** — тесты пишутся с учётом кода, например граничные значения 56 и 57 дней в `LeaveRequestRulesTest`.

## 15.2. Шаблон тест-кейса

| Поле | Содержание |
|---|---|
| ID | TC-NN |
| Название | Коротко: что проверяем |
| Приоритет | Высокий / средний / низкий |
| Роль и предусловия | Под кем входим, какие данные должны быть в БД |
| Шаги | Пронумерованные действия |
| Ожидаемый результат | Что должно произойти по ТЗ |
| Фактический результат | Что произошло |
| Статус | Пройден / Не пройден (+ ссылка на баг) |

Перед прогоном база восстанавливается: `mysql -u root -p < database/schema.sql`, затем `seed.sql`.
Пароль всех тестовых пользователей — `Secret123!`.

## 15.4. Баг-репорты

### BUG-1. Неверная «сегодняшняя» дата с 00:00 до 05:00 по Душанбе
| Поле | Значение |
|---|---|
| Серьёзность | Major — нарушается бизнес-правило, неверные даты в приказах |
| Приоритет | Высокий |
| Окружение | PHP 8.3 (без `date.timezone` в php.ini), MariaDB 10.11, часовой пояс сервера UTC |
| Шаги | 1) В 00:11 по Душанбе войти как teacher1. 2) Подать заявку с датой начала = вчера |
| Ожидается | «Дата начала не может быть в прошлом» |
| Фактически | Заявка принята, на главной — вчерашняя дата |
| Причина | PHP и MySQL работают в UTC (UTC+0), Душанбе — UTC+5. `date('Y-m-d')`, `new DateTimeImmutable('today')` и `CURDATE()` возвращают вчерашний день |
| Исправление | Коммит `fix: use Asia/Dushanbe timezone in PHP and MySQL session`: настройка `timezone` в конфиге, `date_default_timezone_set()`, `SET time_zone` для соединения PDO, дата приказа передаётся из PHP |
| Проверка | TC-11 б) повторён в 00:12 — пройден |

### BUG-2. Учётная запись без карточки сотрудника видит чужие данные
| Поле | Значение |
|---|---|
| Серьёзность | Critical — утечка персональных данных |
| Приоритет | Высокий |
| Шаги | 1) Пользователь с ролью employee, у которого `employee_id = NULL` (карточку удалили, сработал `ON DELETE SET NULL`). 2) Войти, открыть «Отпуска» |
| Ожидается | Пусто или отказ в доступе |
| Фактически | Видны все 14 заявок института; такой «заведующий» видит всех 46 сотрудников и получает их из API |
| Причина | Фильтр в репозитории проверялся через `empty()`: `employee_id = 0` воспринимался как «фильтра нет» |
| Исправление | Коммит `fix(auth): accounts without employee card could see all leave requests`: вход для head/employee без карточки запрещён; фильтры проверяются через `array_key_exists()` |
| Урок | Проверки прав нужно писать так, чтобы при «пустых» данных результат был «запрещено», а не «разрешено всё» (принцип fail-safe) |

### BUG-3. «Сессия устарела» вместо сообщения о большом файле
| Поле | Значение |
|---|---|
| Серьёзность | Minor — данные не портятся, но сообщение вводит в заблуждение |
| Приоритет | Средний |
| Шаги | 1) Открыть форму нового сотрудника. 2) Выбрать в поле «Фото» файл 9 МБ. 3) Сохранить |
| Ожидается | Сообщение о превышении размера файла |
| Фактически | «419 Сессия устарела»; в журнале PHP: `POST Content-Length of 9000411 bytes exceeds the limit of 8388608 bytes` |
| Причина | Запрос больше `post_max_size` — PHP отбрасывает все поля формы, CSRF-токена нет |
| Исправление | Коммит `fix: clear 413 message instead of "session expired" for huge uploads` |

## 15.5. Модульные тесты PHPUnit

```bash
composer install            # установит PHPUnit в vendor/
vendor/bin/phpunit          # или: composer test
```

Ожидаемый вывод:
```
OK (49 tests, 62 assertions)
```

| Тест | Что проверяет |
|---|---|
| `ValidatorTest` (21 тест с наборами данных) | обязательные поля, длина с кириллицей (60 «х» = 60 символов, 120 байт), e-mail, даты (29.02, 31.04, формат), `in`, телефон, «первая ошибка поля», массив вместо строки |
| `LeaveRequestRulesTest` (28 тестов) | корректные даты, начало сегодня, конец раньше начала, начало в прошлом, 56/57 дней (граничные значения), лимит только для ежегодного, длительность через Новый год и в високосном феврале, все переходы статусов, права заведующего (своя кафедра, своя заявка), уровень ОК |

Почему правила вынесены в `App\Services\LeaveRequestRules`: класс не зависит от БД, сессии и `$_POST`,
а «сегодня» передаётся параметром — поэтому тест не «сломается» завтра.

## 15.6. Инструменты отладки

- **DevTools → Network:** код ответа (302, 403, 419, 422), заголовок `Location`, cookie `UHRSESSID`
  (флаги HttpOnly, SameSite=Lax), запросы живого поиска.
- **DevTools → Console:** ошибки JavaScript (их не должно быть ни на одной странице).
- **DevTools → Application → Cookies:** удалите `UHRSESSID` — следующий запрос перенаправит на `/login`.
- **Xdebug:** `xdebug.mode=debug`, точка останова в `LeaveController::decide()` — видно `$leave`, `$user` и результат
  `LeaveRequestRules::nextStatus()`. В XAMPP расширение подключается в `php.ini`.
- **Lighthouse** (DevTools → Lighthouse, режим Desktop/Mobile): цель — Accessibility ≥ 90, Best Practices ≥ 90.
  Типичные замечания и их исправление: контраст текста (цвета из UI-kit проверены), подписи полей (`<label for>`),
  `lang="ru"`, `alt` у изображений.
